# /project runbook

How a person prepares for, runs, reads and clears a graded `/project` attempt
on the AI Venture Studio brief. The design is in
`docs/superpowers/specs/2026-09-30-project-single-entry-design.md`; flags and
the report are in "One command: /project" in `docs/briefv2/README.md`.

## 1. What a human provides before the run

`--preflight-only` prints a numbered list of what is missing, in this order, each
with a `Fix:` line. The checks run in a fixed order with no early exit. When
`gophermind.yaml` is missing or invalid, every check that needs it prints
`not checked` with the fix `fix the settings check first`. The checklist below
follows the preflight order.

- [ ] 1. `repo`: the target is a git work tree on the brief's base branch.
  Fix: `put the repo on branch <base> at <expect-head rev>`.
- [ ] 2. `repo head` (with `--expect-head`): HEAD is the expected commit
  (`goal-baseline`). Same fix as `repo`.
- [ ] 3. `clean tree` (not with `--resume`): nothing changed outside
  `.gophermind/`. Fix: read the dirt with `git -C <repo> status`, then commit or
  discard it.
- [ ] 4. `stale state`: no earlier attempt is left. Fix: clear the attempt
  (section 4) or pass `--resume`.
- [ ] 5. `landing`: the brief's `landing` field is `commit` or `diff_only`.
- [ ] 6. `graded` (with `--graded`): `--expect-head` given, no `--resume`, no
  leftover state.
- [ ] 7. `sandbox`: Fix: `set executor.sandbox: off in <gophermind.yaml> to run
  without one`, or make `sandbox-exec` runnable.
- [ ] 8. `go toolchain`: `go` is on `toolchain.PATH`. Fix: `add <dir of go> to
  toolchain.PATH in <gophermind.yaml>`.
- [ ] 9. `git`: Fix: `install git and put its directory on PATH`.
- [ ] 10. `disk space`: enough free space for the module cache. Fix: `free disk
  space on the volume that holds <executor.go_mod_cache>`.
- [ ] 11. `settings`: `~/.gophermind/gophermind.yaml` exists and loads (unknown
  keys are refused). Fix: `create it (see docs/briefv2/project-runbook.md)`; the
  file is described in section 2.
- [ ] 12. `privacy` (with `--require-private`): Fix: `set privacy.mode:
  private_only and name only private providers in models.strong,
  models.standard and models.any in <gophermind.yaml>`.
- [ ] 13. `provider <name>`: a `base_url` answers. Fix: `start the model server
  (the mini: ssh mini, then check ollama) or fix base_url and base_url_fallbacks
  for <name> in <gophermind.yaml>`.
- [ ] 14. `provider <name> key`: when a provider names an `api_key_secret` the
  vault lacks. Fix: `gophermind brief vault set <api_key_secret>`.
- [ ] 15. `binary` (with `--expect-binary-commit`): the binary was stamped with
  that commit. Fix: `rebuild with scripts/build-dev-binary.sh`.
- [ ] 16. `vault passphrase`: Fix: `export GOPHERMIND_VAULT_PASSPHRASE=<passphrase>`.
- [ ] 17. `vault`: the vault opens with that passphrase.
- [ ] 18. `secret <NAME>` for each declared secret that has no vault value and is
  not generated. Fix: `gophermind brief vault set <NAME>`. For the real brief
  that is `DATABASE_URL` and `TEST_DATABASE_URL`; `JWT_SIGNING_KEY` and
  `STUDIO_LLM_API_KEY` are generated by the command line.
- [ ] 19. `database <NAME>` for each stored postgres URL: the host is loopback
  and accepts connections, and the two URLs name different databases. Fix when
  the connection is refused or the host is not loopback:
  `ssh -N -L 55432:127.0.0.1:5432 mini` (the port is the URL's port). Fix for a
  shared database: `gophermind brief vault set <NAME>`.

The databases are two empty Postgres 15 or later databases, one for
`DATABASE_URL` and a different one for `TEST_DATABASE_URL`, both reached through
the tunnel with URLs that name `127.0.0.1`. Keep the tunnel open for the whole
run. The preflight does not check that a database is empty; reset both before
every attempt.

Set the vault values (the value comes from a terminal prompt or stdin; never
put it in a command line):

```bash
export GOPHERMIND_VAULT_PASSPHRASE=<passphrase>
gophermind brief vault set DATABASE_URL
gophermind brief vault set TEST_DATABASE_URL
```

## 2. gophermind.yaml

`~/.gophermind/gophermind.yaml` (or `$GOPHERMIND_CONFIG_DIR/gophermind.yaml`).
The lines a graded run depends on:

```yaml
privacy:
  mode: private_only
providers:
  - name: mini
    base_url: http://baby-jesus.local:11434/v1
    base_url_fallbacks:
      - http://10.8.0.6:11434/v1
    visibility: private
models:
  strong: [mini/<model>]
  standard: [mini/<model>]
  any: [mini/<model>]
toolchain:
  PATH: <directory of go>:/usr/bin:/bin
```

`<model>` is the model name the server serves, and each model needs its
`context_tokens` under the provider's `models` list (see "Settings" and
"Executor settings" in the README). Every tier names only private providers.
`toolchain.PATH` is the only path the executor uses to find `go`.

## 3. The graded command

One invocation, never `--resume`, output to a log file under the scratchpad
(`$SP`). Build the stamped binary first with `scripts/build-dev-binary.sh` (it
needs a clean, pushed tree).

```bash
gophermind-dev project gophermind-lib/briefv2/testdata/ai-venture-studio-server-brief.md \
  --repo "$HOME/OtherProjects/AIVentureStudio" \
  --generate JWT_SIGNING_KEY=hex32 --generate STUDIO_LLM_API_KEY=placeholder \
  --require-private --expect-head goal-baseline \
  --expect-binary-commit "$(git rev-parse --short HEAD)" > "$SP/attempt.log" 2>&1; echo "exit $?"
```

`--expect-head` makes the attempt graded. To check everything first, add
`--preflight-only`: exit 0 means ready, exit 6 prints the list of section 1.

## 4. State and clearing

`gophermind-dev project <brief> --repo <repo> --print-state-paths` prints every
path, so nothing is guessed. Per project (keyed by the brief id):

| What | Where | On a clear |
|---|---|---|
| run folder | `<repo>/.gophermind/<id>/` | archive, then delete |
| scratch folder | `<repo>/.gophermind/<id>-scratch/` | delete |
| git exclude line | `<repo>/.git/info/exclude` | keep |
| work branch | the work branch (`gm/<id>` unless the brief sets `work_branch`) | `git branch -D`; reset and clean do not remove it |
| work tree and HEAD | the repo | `git reset --hard goal-baseline` |
| run record | `~/.gophermind/runs/<id>.json` | delete the file |
| vault, `gophermind.yaml`, `gomodcache/` | `~/.gophermind/` | keep |
| the two databases | external | drop and recreate |

Clear with `scripts/clear-project-state.sh <repo> <id> <work-branch> <archive-dir>`.
It checks every argument before the first git command and exits 1, touching
nothing, on any failure. The repo must be an absolute path with no `..`
component; it is resolved through symlinks first, and the resolved path must not
be `/`, must not be `$HOME` and must not contain `$HOME`, and must hold a `.git`
directory. The id must match `gm-YYYY-MM-DD-NNN`. The work branch, `BASE_BRANCH`
(default `main`) and `BASELINE` (default `goal-baseline`) must be plain ref
names (letters, digits, `/ _ . -`; no leading dash; no `..`). The work branch
must not be the base branch. The archive directory must exist and be outside
the repo.

Before any destructive step the script also checks that `BASELINE` names a
commit and that `BASE_BRANCH` is a branch of the repo, and that
`<repo>/.gophermind` is not a symlink (it checks again before the final
removal, because `git reset --hard` can restore a tracked symlink). A repo
whose `.git` is a file (a worktree or a submodule) and a bare repo are refused
with `repo has no .git directory`.

Then it archives, into the archive directory:

- the WHOLE `<repo>/.gophermind` folder (every run id, not only this one) as
  `attempt-<id>.tar.gz`, because `git clean -fdx` removes untracked files,
  including the run folders of other ids; this step is skipped when
  `<repo>/.gophermind` does not exist;
- the work branch, if it exists: `work-branch-tip.txt` (its tip commit) and
  `work-branch.bundle` (verify it with `git bundle verify`), so its commits are
  recoverable after `git branch -D`;
- `removed-files.txt`, the names (no contents) of the files `git clean` will
  remove.

After the archive it puts HEAD on the base branch, deletes the work branch,
runs `git reset --hard goal-baseline` (`BASELINE` overrides this revision) and
`git clean -fdx -e .remember`. Ignored files are removed too: `.env` files and
build output in the repo go as well, and only `.remember` is kept. It then
removes what clean left behind by exact path: the run folder, the scratch folder
and `$GOPHERMIND_CONFIG_DIR/runs/<id>.json` (default
`~/.gophermind/runs/<id>.json`). Every git call after validation is
`git -C <repo>`.

```bash
BRIEF=gophermind-lib/briefv2/testdata/ai-venture-studio-server-brief.md
R="$HOME/OtherProjects/AIVentureStudio"; ID=gm-2026-09-29-002
# the work branch is the git_branch_delete line, so a brief with work_branch works
BR="$(gophermind-dev project "$BRIEF" --repo "$R" --print-state-paths | awk -F'\t' '$1=="git_branch_delete"{print $3}')"
scripts/clear-project-state.sh "$R" "$ID" "$BR" "$SP"
# then reset both databases, and verify: git status clean, HEAD == goal-baseline,
# no work branch, no run folder, and a --preflight-only run exits 0
```

Use the git on `PATH`; never `git checkout`, `git stash`, `git worktree add` or
`--gw-force`. Wrapper warning: the user's git wrapper
(`~/.local/bin/git-wrapper/git`) may block `git reset --hard goal-baseline`,
`git clean -fdx -e .remember` and `git branch -D` on the work branch (the
script runs all three). The orchestrator tests these three in the target repo
first (on a throwaway branch or a copy) and asks John for explicit sign-off before any override.

## 5. Reading and archiving a run before clearing

Clearing removes the run folder, and there is no database to read afterwards.
Read first, then archive.

- `<run folder>/_state/project.json`: the whole account of the run (mode, graded
  and `graded_valid`, preflight, providers, secrets by name and source, the
  ambiguity settlement, approval hashes, plan size, `by_node_class`, status,
  `stop_reason`, `exit_code`).
- `<run folder>/UNDERSTANDING.md`: what the run confirmed, with every assumption
  marked `[assumed, nobody was asked]`.
- `<run folder>/report.json`: the executor's report.
- `gophermind brief status <id>`: each stage and what the run waits for.
- `gophermind brief calls <id>`: the model call ledger.

Archive the run folder (the clear script archives the whole `.gophermind` folder for you), which holds the ledger `_state/calls.jsonl`, the
events `_state/events.jsonl` and `attempts/` (the saved attempts), with the
`tar` line in section 4, and write the attempt record from it.

## 6. Exit 6 and exit 7

Exit 6: the preflight failed. Nothing was planned or built, no run folder was
created, and the attempt count is unchanged. Provide the numbered items and run
again.

Exit 7: a harness fault. The repository could not be opened, the sandbox was
refused, the settings are invalid, the plan changed since the run started, or a
leaf is held by a live worker. It is a fault in the setup or the harness, not a
failed build; read `_state/project.json` and the stderr log before deciding
whether to clear.
