# v2 Executor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the executing half of the v2 brief-to-build engine: a context packer and reply checker, a darwin `sandbox-exec` sandbox, a command runner, a git landing layer, a loopback forward proxy, a run report, and `executor.Run`, which takes an approved plan and runs every function leaf, wave by wave, through a bounded escalation ladder to `verified`, checks the whole repo after each wave, repairs attributed failures, runs every acceptance bullet against the built server, proves `Acceptance passed: N of N`, lands GopherMind's own commits on `main` by fast-forward, resumes after a kill without repeating a model call for a finished leaf, and exposes `gophermind brief run <id>` and `brief report <id>`.

**Architecture:** New packages under `gophermind-lib/briefv2/`, dependencies pointing downward: `pathsafe`, `sandbox`, `gitland`, `proxy` (leaves) <- `runner` (uses `sandbox`) <- `packer` (uses `contract`) <- `report` (uses `ledger`, `blackboard`, `planner` readers) <- `executor` (uses everything, plus the built `planner`, `router`, `settings`, `human`, `events`, `execenv`, `tree`, `contract`, `brief`). Every child process runs in the sandbox; the model can only ever change the one file its node names; every state change goes through the blackboard; the run ends in exactly the states of spec 7.1. The commands live in `cmd/gophermind/brief_run.go`. Everything runs offline in tests against a scripted `provider.Fake` and a tiny `greeter` repo.

**Spec:** `docs/superpowers/specs/2026-09-30-v2-executor-design.md` (binding; read it first, all of it). Planner plan and spec: `docs/superpowers/plans/2026-09-29-v2-planner-core.md`, `docs/superpowers/specs/2026-09-29-v2-planner-core-design.md`. Handoff reference: `docs/briefv2/handoff/` (`prompts/05-implement.md`, `prompts/06-revise.md`, `BUILD_PLAN.md` items 9 to 14). Bar for a perfect release: `docs/GOAL.md` in the main checkout.

**Tech Stack:** Go (the module's version), the standard library (`go/parser`, `go/format`, `go/printer`, `os/exec`, `net/http`, `crypto/sha256`), `modernc.org/sqlite` and `gopkg.in/yaml.v3` (already dependencies), the `git` CLI behind an interface, `/usr/bin/sandbox-exec` on darwin. No new dependency.

## Global Constraints

- Pure Go, no cgo, no new dependency. New code lives under `gophermind-lib/briefv2/<package>/` (module `gophermind/gophermind-lib`) and `cmd/gophermind/brief_run.go`. Do not modify any existing package except the named exceptions: Task 1a (execenv `GoEnv` and `NO_PROXY`; blackboard `Attempt.ReplySHA256`), Task 1b (planner dependencies, approval hash, leaf tests file, exported readers), Task 2 (planner uses `pathsafe`; `testwriter.go`, `nofollow_*.go`), Task 9a (`settings` executor section), Task 15 (`cmd/gophermind/brief.go` routing and usage; `docs/briefv2/README.md`).
- Tests never use the real network (`httptest` on loopback, `file://` module proxies, and a `GOPROXY` of `file://...` are allowed) and never read or write the real `~/.gophermind`: use `t.TempDir()` and `t.Setenv("GOPHERMIND_CONFIG_DIR", ...)`. The one exception is the sandbox test that needs a directory under the real `$HOME` (Task 3); it makes it with `os.MkdirTemp(home, "gm-sbtest-")`, never touches `~/.gophermind`, and removes it only through a guarded delete that checks the `gm-sbtest-` prefix and that the parent is `home`. Every delete in this plan, in code or in a shell block, assigns its target to a variable, tests it (non-empty, expected prefix and parent, never `/` or the home directory) and only then deletes; the shell form is `rm -rf -- "${target:?}"`.
- Prompt text and reply text are never stored, logged, put in an event, a blackboard row, a ledger row or an error. Only sizes and SHA-256. Runner output (build, vet, test, acceptance) lives in memory only. No secret value is ever written anywhere or appears in an error message.
- Errors never quote reply text or command output. Reuse the planner's helpers for decoding errors (`jsonErr`, `schemaErr`, `syntaxErr` in `planner/safeerr.go`; Task 1b exports the ones the executor needs as `planner.JSONErr` and `planner.SyntaxErr`). A parser error that can quote its input (`go/parser`, `go/scanner`, `json`) is described by kind, line/column and size, never by its message text.
- Tests are TDD: write the failing test, run it and see it fail for the right reason, then implement. Table tests where a list of cases is given. Tests pass with `-race`; code is gofmt-clean and `go vet` clean. No em dashes and no emojis in code, comments, docs or commit messages.
- In a git worktree the ignored `desktop/frontend/dist` folder is missing: build with `go build ./cmd/... ./gophermind-lib/...` in `/Users/jbrahy/OtherProjects/PMSLLC/gophermind-planner-core`. Test with `go test -race ./gophermind-lib/briefv2/<pkg>/...`.
- The git wrapper on this machine blocks `git stash`, `--gw-force`, and (in some setups) `git checkout`. Never use them in your own shell. `gitland` uses `git switch` and `git restore` for the same effects (Decision E4), so its tests run under the wrapper; if `git` on `PATH` is the wrapper and a test still fails because of it, tests may set `GITLAND_TEST_GIT=/usr/bin/git` (the package honors it only when set).

## Decisions specific to this plan

| # | Choice | Why |
|---|---|---|
| E1 | `packer` owns both halves of the reply contract: `Pack` (the prompt) and `ParseReply` / `ImportPolicy.Check` (the reply). The system line of every executor call is `packer.SystemPrefix + stage` (`"GopherMind executor. Stage: implement:fn-x"`) | A scripted fake provider finds the stage from the system message, as the planner's fixture provider does; reply checks are pure and testable without a repo |
| E2 | The reply parse function handed to `router.CallParsed` returns an error only for `malformed` replies (no code, unparseable Go, wrong package, signature mismatch, empty). `forbidden_write` and `import_not_allowed` are decided after the call from the same parse result and are failed attempts, never router retries | Spec 7.2 table: only `malformed` gets the router's cheap repair; a forbidden reply must never be written and must not be "fixed" by asking again with its text appended |
| E3 | The sandbox denies all non-loopback network in every mode. The deps step reaches the module proxy through the harness proxy over loopback (the proxy process is the harness, outside the sandbox). `Profile` has no proxy-host rule | Ruling S1 below. Simpler and strictly tighter than the spec's "outbound to the module proxy host": the sandboxed `go` process never opens an outbound socket |
| E4 | `gitland` uses `git switch` / `git restore` / `git merge --ff-only` and never `checkout`, `reset`, `rebase`, `push`, `stash`, `clean`, `--force` | Equivalent effect; `checkout` is blocked by the developer's wrapper; a test asserts the argv of every spawned command |
| E5 | `gitland.Repo` gains `Restore(paths []string) error`, `Head() (string, error)`, `Branch() (string, error)` and `LeafCommit(nodeID string) (string, bool, error)` beyond the spec's list | Spec 6 rule 7 and 8.1 step 6 need "revert to HEAD / remove untracked" and the report needs the landing commit, and resume must find a leaf's existing commit so that no leaf is committed twice (spec 10); the interface still cannot express push, force, reset or rebase |
| E6 | The executor gets a leaf's test file path and test function from a new `_state/leaf_tests.json` (`{node: {test_file, test_func, sha256}}`) written by the planner's finish step (Task 1b), not from `_state/test_files.json`, which is a plain list of paths | Spec 15.4 assumed the list carried function names; it does not. The sha256 lets the executor prove no test file was edited between planning and running |
| E7 | `dependencies.json` is written by the contract stage when the outline pass finishes (empty list when none), read with `planner.ReadDependencies`, and its bytes are hashed in `hashedFiles` | Spec 15.1 |
| E8 | Runner output is kept in a `runner.Output` value whose text is reachable only through a method; nothing in `runner` or `executor` has a `String()`, `%v` or JSON form that includes it | Makes an accidental log of output a compile-visible act, and a canary test greps for it |
| E9 | `executor` internal tests share one rig (`rig_test.go`, Task 9b: repo, plan, board, ledger, settings with named chains `a/m1`, `b/m2`) and one scripted harness (`harness_test.go`, Task 9c: a `provider.Fake` that pops replies per stage from the `Script`, records every request, wires the router and the gate), both over the one greeter fixture | Every later executor task needs the same fake and the same plan; E2E (Task 16) reuses them (I9) |
| E10 | A leaf's package for commands is `./<dir of contract.file>`; a leaf's tests are run with `-run ^<TestFunc>$` | Planner's `testCommand` does the same (`go test ./dir -run ^TestX$`) |
| E11 | The sandbox profile has no unix-socket allow (I5) | `go build`, `go vet` and `go test` use pipes; a blanket socket allow would reach an ssh agent or a docker socket. `TestSandboxGoBuildAndTest` proves the toolchain needs none |
| E12 | The sandbox denies writes to `<repo>/.git`, and `gitland` starts every git command with `-c core.hooksPath=/dev/null -c core.fsmonitor=false -c core.sshCommand=` (C4) | The repo is writable to a model-written test; without both layers a test could set `core.fsmonitor` or `core.sshCommand` in `.git/config`, or plant a hook, and the harness's own later `git status` or `git commit` would run it outside the sandbox |
| E13 | Every executor Go command runs with `CGO_ENABLED=0` (from the toolchain environment), and `-race` is proved to work that way by Task 4's `TestRaceDetectorNeedsNoCgo` (I10) | cgo is forbidden in leaf code anyway (spec 6.1 scan); the plan no longer asserts that `-race` works without cgo, it tests it, and names the fallback if a machine disagrees |
| E14 | `gitland.Repo.Start(base, work, allowDirty []string)`; a fresh run passes the plan's test-file paths (C3) | The Test-writer's test files are always uncommitted at a fresh start, so a strict clean-tree rule would fail every run; the Wave 0 commit is what commits them. The executor checks the subset first for a friendly message, and `Start` enforces the same rule |
| E15 | The deps step's writable module cache is `runner.Spec.ModCacheWritable`, not a second `runner.Config` (C2) | One `Config` means a leaf command cannot be given a writable cache by a wiring mistake; only `rc.goCmd` in `envDeps` mode sets the per-call field |
| E16 | The greeter fixture (5 leaves, 3 waves, spec 18) is defined once, in Task 9b, and every later task and Task 15 reuse it (I9) | Two fixtures (the planner's 3-leaf greeter and an executor one) made tests disagree on counts and waves |
| E17 | Leaf and acceptance Go commands set `GOFLAGS=-mod=readonly -buildvcs=false` | `-buildvcs=false` stops `go build` from running the repo's `git`, which a test could have influenced |

### Spec gaps and contradictions, and the ruling taken

| # | Spec text | Problem | Ruling |
|---|---|---|---|
| S1 | 6.1 Network: "outbound to the module proxy host through the harness proxy" | The proxy is the harness, on loopback; the sandboxed child only ever needs loopback | Loopback only in every mode (E3); the proxy does the outbound work |
| S2 | 6.1 Writes: `GOMODCACHE` writable; 14: leaf commands `GOPROXY=off -mod=readonly` | A writable module cache in a leaf sandbox lets a model-written test poison it, which R7 lists as a cost | `GOMODCACHE` is read-only in every sandbox except the deps step, where the per-call `runner.Spec.ModCacheWritable` (E15) makes the profile writable for that one command. Task 10 proves `go build` and `go test` work with it read-only and that the deps step can fill it |
| S3 | 8.1 Stubs: "zero-value returns after it for the compiler" | `panic` is a terminating statement, so trailing returns are unnecessary, and `go vet` flags them as unreachable code | The stub body is exactly `panic("gm: not implemented")` |
| S4 | 6 rule 1: `pathsafe.Resolve` rejects `_test.go`; 15.3: the planner's `safeTestPath` (which requires `_test.go`) moves to `pathsafe` | One function cannot both require and forbid `_test.go` | Two entry points: `pathsafe.ResolveTest` (planner behavior, unchanged) and `pathsafe.ResolveSource` (executor) |
| S5 | 7.3 bound: formula `entries*(1+fix)*(rev+1)+rev`, then "11 implement plus 2 revise" | With one entry, 2 fixes, 2 revisions the formula gives 9 + 2 = 11 total | 9 implement plus 2 revise = 11; `TestLeafCallBound` asserts implement `<= entries*(1+fix)*(rev+1)` and revise `<= rev`, each excluding router repair rows |
| S6 | 15.6 and X12: "SQLite backend migration adds a column" | Attempts are one JSON text column; a new struct field needs no migration | `ReplySHA256` is a JSON field; old rows decode to empty; no migration |
| S7 | 7.3 rung 2: temperature 0.3 "after a first fix failure" | Ambiguous | First try and first fix at 0, every later fix at 0.3 |
| S8 | 19: exit 3 "waiting on a human (file gate)" vs 7.1 human `stop` = 4 | `Gate.Escalate` with the file gate returns `human.ErrWaiting` | `ErrWaiting` ends the run `escalated`, `stop_reason: "waiting_on_human"`, exit 3; the leaf stays `escalated`; the next `brief run` asks the gate again |
| S9 | 7.2: `malformed` is an `error` verdict that "does not consume a fix attempt" | If every reply of an entry is malformed the router excludes the entry and returns `ChainExhausted`; unbounded otherwise | An entry that ends in `ChainExhausted` (malformed after the router repair, provider failure, too long, auth, missing model) is abandoned for the revision and the ladder moves on; bounded by the entry count |
| S10 | 14 Critical failure: "three in a row on one node" | "In a row" across leaf attempts | Counter kept per node in memory and in `_state/executor.json` (`critical_streak`); any attempt with no critical failure resets it |
| S11 | 12 Start: "on a fresh run the tree must be clean" and Wave 0 commits "every `*_test.go` the Test-writer placed" | The Test-writer leaves its test files uncommitted, so a clean-tree rule fails every fresh run (contradiction) | `Start` takes `allowDirty`; a fresh run allows exactly the plan's test files and nothing else (E14) |
| S12 | 7.1: blocked is "a `depends_on` node not `verified` when its wave is reached"; goal 1: no leaf ends without a reason | After a stop, leaves of unreached waves are neither blocked by that rule nor named | `Report.Failures` lists every non-verified leaf: `blocked by <dep>` when a direct dependency is not verified, else `not_run: <stop reason>`; a test asserts the list is complete |
| S13 | 8.3 escalation "exactly as in 7.4" (skip lets the run continue) | After a skipped integration failure the failing code is committed, so every later wave would attribute failures to a terminal leaf | A `skip` on an integration escalation ends the run `failed`, `stop_reason: "integration_skipped"`; a skip on a leaf's own ladder still continues |
| S14 | 10: "fresh when the blackboard has no rows past pending" | A crash after Wave 0 but before any claim leaves all rows pending yet the branch and Wave 0 commit exist | Fresh versus resume is decided by `_state/executor.json` (`StartedAt`, `Wave0Done`); `Report.Resumed` is true only once a row is past `pending` (R11 unchanged) |
| S15 | 9: an acceptance requirement without a test "is a failure of the run before anything is started" | The mapping code is written in Task 13, the start in Task 10 | Task 13 adds the tripwire call to `startRun`; before it, nothing can reach `verified` without acceptance (Task 12b stub) |
| S16 | 18: the greeter has 5 leaves in 3 waves; the planner plan's greeter has 3 leaves | Tests written on the 3-leaf fixture would not match spec counts | One 5-leaf fixture, defined in Task 9b (E16) |

## Review Focus

1. Sandbox containment: with the profile, a child cannot write outside the repo, scratch and caches, cannot write `.gophermind/<id>` or `<repo>/.git`, cannot read the real home directory, cannot connect to a non-loopback address, and can use loopback. Missing `sandbox-exec` is a preflight failure before any model call; off-darwin refuses unless `sandbox: off`. (Task 3, `TestSandboxDeniesWriteOutside`, `TestSandboxDeniesRunDirWrite`, `TestSandboxDeniesGitWrite`, `TestSandboxDeniesHomeRead`, `TestSandboxDeniesNonLoopback`, `TestSandboxAllowsLoopback`, `TestSandboxRequiredOffDarwin`; Task 6, `TestGitInvocationsNeutraliseRepoConfig`; Task 10, `TestLeafCommandsOffline`)
2. No leaf is ever silently skipped: a `verified` run has every leaf `verified`; blocked and unreached leaves are named with a reason; skip yields `failed`; a nil gate or no answer is `stop`. (Task 11b, `TestBlockedLeavesReported`, `TestGateSkipFailsRun`, `TestNilGateStops`; Task 12b, `TestVerifiedImpliesEveryLeafVerified`, `TestReportListsEveryUnverifiedLeaf`; Task 13, `TestFinishVerifiedImpliesEveryLeafVerified`)
3. No reply text, prompt text, command output or secret reaches an error, an event, the blackboard, the ledger, a log or a file; only class, test names, counts, sizes and hashes. (Task 5b, `TestNoPromptTextPersisted`; Task 11a, `TestNoReplyOrOutputInPersistedFailure`; Task 16, `TestExecutorE2E` canary grep)
4. Path safety: the model never names a path; the only file written for a leaf is `contract.file`, through `pathsafe`; stray writes are caught by a git status snapshot after every attempt and after every wave. (Task 2, `TestPathsafeTable`; Task 9c, `TestReplyCannotNamePath`, `TestStrayFileFailsAttempt`; Task 11a, `TestStrayWriteFailsAttempt`; Task 12a, `TestStrayFileFailsWave`)
5. Acceptance N of N is proven: N comes from `requirements.json`, a bullet with no root test fails the run, the proof is a recorded triple of command, exit code and output hash, the built binary (never an installed one) is what runs, and leftovers are killed. (Task 13, `TestAcceptanceCountFromRequirements`, `TestAcceptanceUsesBuiltBinary`, `TestAcceptanceKillsProcessGroup`, `TestAcceptanceProofFile`)
6. Resume repeats no model call for a finished leaf, checks the file on disk first, preserves attempts and numbering, makes exactly one commit per leaf, and never stashes or discards. (Task 14, `TestResumeAfterKill`, `TestResumeNoDuplicateCalls`, `TestResumeVerifiesFileOnDiskFirst`, `TestReplyHashPersistedAcrossResume`, `TestResumeRefusesForeignDirt`)
7. The stub swap is exact: stub removed before the real file is written, stub restored after any failure, a leaf committed only on pass, the commit removes the stub, every commit builds. (Task 9c, `TestStubSwapOnFailureRestoresStub`, `TestLeafCommitRemovesStub`; Task 10, `TestStubsBuildAtEveryCommit`)
8. Git landing is GopherMind's only, on a work branch, ending as a fast-forward of `main`; the interface and the CLI implementation cannot push, force, reset or rebase; a moved `main` blocks landing with the work branch intact; a fresh run accepts exactly the Test-writer's files as dirty. (Task 6, `TestNoPushForceResetRebase`, `TestFinishFastForward`, `TestLandingBlockedWhenMainMoved`, `TestStartAllowsListedDirtyPaths`)
9. The model-per-task-type report matches a hand count and its last two lines are the proof lines. (Task 8, `TestReportHandCount`, `TestSummaryEndsWithProofLines`)
10. `max_run_minutes` and SIGINT end the run cleanly and resumably: claims released, report written with `interrupted`, exit 5, no new claim after the limit. (Task 14, `TestMaxRunMinutesStopsCleanly`, `TestInterruptReleasesClaims`)

```go
package sandbox

type Profile struct {
	Repo             string   // read and write
	RunDir           string   // <repo>/.gophermind/<brief-id>: write denied, read allowed
	Scratch          string   // read and write; HOME and TMPDIR of every child
	GoCache          string   // read and write
	GoModCache       string   // read only, unless ModCacheWritable
	ModCacheWritable bool     // true only for a command whose runner.Spec sets ModCacheWritable: the deps step (E15)
	ReadOnly         []string // toolchain roots: GOROOT, the directories of go and git, PATH entries
	Home             string   // the real home directory; empty means no home rule
}
// Writes to <Repo>/.git are always denied; there is no field for it because the rule is not optional (E12).

// Text returns the SBPL profile. Every path is resolved with filepath.EvalSymlinks
// (sandbox-exec matches real paths: /var is /private/var) and must be absolute and
// free of '"', '\\', NUL and newline, else Text returns an error naming the field.
func (p Profile) Text() (string, error)

// Wrap returns cmd rewritten to run under sandbox-exec: Path becomes the resolved
// sandbox-exec binary and Args become {"sandbox-exec", "-p", <profile>, "--", <orig path>, <orig args...>}.
// Dir, Env, SysProcAttr, Stdin/Stdout/Stderr are copied unchanged.
func Wrap(cmd *exec.Cmd, p Profile) (*exec.Cmd, error)

// Preflight verifies sandbox-exec exists and that a minimal profile loads and runs /usr/bin/true.
func Preflight(ctx context.Context) error

// Required reports what settings and platform allow: on darwin "on" is default and "off" is honored;
// on any other GOOS only an explicit "off" is accepted and anything else returns ErrSandboxRequired.
func Required(mode, goos string) (enabled bool, err error)

var ErrSandboxRequired = errors.New("sandbox: this OS has no sandbox; set executor.sandbox: off to run without one")
```

**Profile text** (`Text()` builds exactly this, in this order; later rules win in SBPL, so the denies precede the specific allows):

```go
var b strings.Builder
b.WriteString("(version 1)\n(allow default)\n")
b.WriteString("(deny file-write*)\n")
// writes: repo, scratch, gocache, (modcache when writable), and two device nodes
fmt.Fprintf(&b, "(allow file-write* %s (literal \"/dev/null\") (literal \"/dev/tty\"))\n", subpaths(writes))
// <repo>/.git is denied to model-written processes (E12): a test that could write .git/config (core.fsmonitor,
// core.sshCommand) or a hook would get code run by the harness's own later git commands. subpath covers a .git
// directory, literal covers the .git file of a linked worktree. Both come after the repo allow.
fmt.Fprintf(&b, "(deny file-write* (subpath %q) (literal %q))\n", repo+"/.git", repo+"/.git")
// the run folder is denied to model-written processes; this is more specific and comes after the allow
fmt.Fprintf(&b, "(deny file-write* (subpath %q))\n", runDir)
if home != "" {
	fmt.Fprintf(&b, "(deny file-read* (subpath %q))\n", home)
	// reads: everything writable, the modcache, the toolchain roots
	fmt.Fprintf(&b, "(allow file-read* %s)\n", subpaths(reads))
	// the run folder and .git stay denied for writes even though their parent is writable
	fmt.Fprintf(&b, "(deny file-write* (subpath %q) (literal %q))\n", repo+"/.git", repo+"/.git")
	fmt.Fprintf(&b, "(deny file-write* (subpath %q))\n", runDir)
}
b.WriteString("(deny network*)\n")
b.WriteString("(allow network-outbound (remote ip \"localhost:*\"))\n")
b.WriteString("(allow network-inbound (local ip \"localhost:*\"))\n")
b.WriteString("(allow network-bind (local ip \"localhost:*\"))\n")
```

There is deliberately no unix-socket rule (I5, decision E11): `go build`, `go vet` and `go test` talk to their children through pipes, the harness needs no socket inside the sandbox, and a blanket `(allow network* (remote unix-socket))` would let a child reach local daemons such as an ssh agent or a docker socket. `TestSandboxGoBuildAndTest` proves the toolchain works without it; if a real toolchain step ever needs one, add the narrowest `(allow network-outbound (remote unix-socket (path-literal "<exact path>")))` and justify it in the commit message.

`%q` is acceptable only because the validation above already rejected `"` and `\`. `subpaths` renders `(subpath "<p>")` for each path. The `.git` and run-folder denies are repeated after the read allow only so the order rule is obvious; keep both copies.

**Behavior rules:**
- `Wrap` returns an error, not a silently unsandboxed command, if `sandbox-exec` cannot be located (`exec.LookPath`, then `/usr/bin/sandbox-exec`).

**Behavior rules:**
- `Run` builds `exec.Command` (not `CommandContext`), sets `SysProcAttr{Setpgid: true}`, `Env` exactly as given, `WaitDelay = Grace`, and `Stdout = Stderr = cappedWriter`. Under a sandbox the command is rewritten by `sandbox.Wrap` after these are set, with `*Config.Sandbox`, or with a copy of it whose `ModCacheWritable` is true when `Spec.ModCacheWritable` is set. A wrap error is `Result.Err`; a command is never run unsandboxed because wrapping failed.
- The context and the timeout are watched by a select on `cmd.Wait`. On either, the whole process group is sent SIGKILL (`syscall.Kill(-pid, SIGKILL)`), then `Wait` is drained. **After every run, ended or killed, the group is killed once more**, so a server or `sleep` a command backgrounded cannot outlive it (spec 9). `sandbox-exec` execs the target, so the leader pid is the group id.
- The capped writer counts and hashes every byte and keeps the first `OutputCap` bytes. It is safe for the two concurrent copiers that `os/exec` starts when `Stdout == Stderr` (one mutex).
- `CheckLeaf` stages: (1) `gofmt -l <files>` listing anything is class `malformed` (the file did not pass `go/format`, spec 6 rule 5); (2) `go build ./<Dir>` class `build`; (3) `go vet ./<Dir>` class `vet`; (4) `go test ./<Dir> -run ^<TestFunc>$ -count=1 -json -timeout <TestTimeout>`. Test classification, first match wins: `TimedOut` on the process or a `panic: test timed out` output line: `test_timeout`; `BuildFailed`: `build`; `Panicked`: `test_panic`; any `Failed` name or `PkgFailed`: `test_fail`; `Events == 0`: `no_tests_ran`; top-level `<pkg>.<TestFunc>` not in `Passed`: `test_fail` with the func name; otherwise pass. Zero events is never a pass (R4).
- `go` and `gofmt` are found by the caller's toolchain `PATH` when building `Argv`; `runner` itself never reads `os.Environ`. `New` does not locate binaries; `Argv[0]` relative is a `Result.Err`.
- Verdict `Names` are `SafeName`d, sorted, capped at 8 and `Reason()` joins them; `Reason` never includes compiler or test output, a panic message, or a reply line.
- `ParseLocations` accepts `path.go:12:3:` and `path.go:12:` (compiler and vet, optionally prefixed by `vet: `), and `\t/abs/path.go:12 +0x..` (panic stacks). Absolute paths are made repo-relative when under `repo` and dropped otherwise; `./` prefixes are stripped; GOROOT and module-cache paths are dropped.
- `go test -json` shapes to handle: `{"Action":"run|pass|fail|skip|output|start","Package":"p","Test":"TestX/sub","Output":"..."}`; a package with a compile error carries `"FailedBuild":"p"` on Go 1.24+ and an output line `[build failed]` before; a panic prints `panic: ` in an output event and the test never gets a terminal action; the race detector prints `WARNING: DATA RACE` and the package (not a test) fails.

**Subtle code** (the group kill and the capped writer; write these first, everything else is plumbing):

```go
type cappedWriter struct {
	mu        sync.Mutex
	buf       []byte
	limit     int
	size      int
	h         hash.Hash
}

func (w *cappedWriter) Write(p []byte) (int, error) {
	w.mu.Lock()
	defer w.mu.Unlock()
	w.size += len(p)
	w.h.Write(p) // hash of everything, kept or not
	if room := w.limit - len(w.buf); room > 0 {
		if len(p) < room {
			room = len(p)
		}
		w.buf = append(w.buf, p[:room]...)
	}
	return len(p), nil
}

func (r *Runner) Run(ctx context.Context, s Spec) Result {
	// ... validate Argv[0] absolute, build cmd, wrap ...
	if err := cmd.Start(); err != nil {
		return Result{ExitCode: -1, Err: startErr(err)} // startErr never includes stderr
	}
	pgid := cmd.Process.Pid
	done := make(chan error, 1)
	go func() { done <- cmd.Wait() }()
	var timeout <-chan time.Time
	if s.Timeout > 0 {
		t := time.NewTimer(s.Timeout)
		defer t.Stop()
		timeout = t.C
	}
	var res Result
	select {
	case <-done:
	case <-timeout:
		res.TimedOut = true
		_ = syscall.Kill(-pgid, syscall.SIGKILL)
		<-done
	case <-ctx.Done():
		res.Canceled = true
		_ = syscall.Kill(-pgid, syscall.SIGKILL)
		<-done
	}
	_ = syscall.Kill(-pgid, syscall.SIGKILL) // leftovers: always, even after a clean exit (ESRCH is fine)
	// ... fill ExitCode, Duration, Out from the writer ...
	return res
}
```

```go
package gitland

// Repo is the whole surface the executor may use. There is no Push, Force, Rebase or Reset.
type Repo interface {
	// Start verifies base exists. When work does not exist it requires every dirty path to be one of allowDirty
	// (exact repo-relative paths; nil means the tree must be clean) and creates work from base's tip; when it exists
	// it only switches to it (resume: the executor applies the dirt policy). allowDirty exists because the
	// Test-writer's test files are always uncommitted when a fresh run starts (decision E14); they are committed
	// by CommitWave0.
	Start(baseBranch, workBranch string, allowDirty []string) error
	CommitWave0(paths []string) (string, error)                       // test files, type files, stubs, go.mod, go.sum; returns the short hash
	CommitLeaf(nodeID, title string, add, remove []string) (string, error)
	CommitRepair(nodeID string, round int, add []string) (string, error)
	// Finish makes the empty final commit on the work branch, then fast-forwards base to it.
	Finish(msg string) (string, error)                                // returns the final short hash; ErrLandingBlocked when base moved
	Dirty() ([]string, error)                                         // sorted repo-relative paths, tracked changes and untracked files
	Diff(base string) ([]byte, error)                                 // working tree against base, including new files, for diff_only
	Restore(paths []string) error                                     // E5: tracked paths back to HEAD (index and tree); untracked files removed
	Head() (string, error)                                            // short hash
	Branch() (string, error)                                          // current branch name
	// LeafCommit finds the leaf commit for nodeID on the current branch (subject "gm(<id>): ", trailer GopherMind-Node
	// equal to the id, not a repair) so a resumed run never commits a leaf twice (spec 10). ok is false when none exists.
	LeafCommit(nodeID string) (hash string, ok bool, err error)
}

var (
	ErrLandingBlocked   = errors.New("gitland: landing_blocked: base branch moved, fast-forward is not possible")
	ErrDirtyTree        = errors.New("gitland: working tree is not clean")
	ErrNothingToCommit  = errors.New("gitland: nothing to commit for the named paths")
	ErrIndexNotClean    = errors.New("gitland: the index holds changes the commit did not name")
	ErrForbiddenGitArgs = errors.New("gitland: refused git arguments")
)

func NewCLI(dir, runID string) (*CLI, error)

// still lives directly under os.TempDir() and still has the "gm-gitland-home-" prefix, and only then deletes it.
func (c *CLI) Close() error

// ValidateLanding is called by the executor before Start. The brief schema's landing values are
// diff_only, commit and pull_request; "" is treated as commit. "pull_request" (and any other value)
// returns an error naming the field, and is never downgraded silently (spec 12, X7): `brief field landing: "pull_request" is not supported by this executor`.
```

**Behavior rules:**
- **Binary and isolation.** `git` is `$GITLAND_TEST_GIT` when set, else `exec.LookPath("git")`. Every command runs with `Dir` set, `Env` built from scratch: `PATH`, `HOME` set to a private empty temp dir made in `NewCLI` (removed by `Close`), `LANG=C`, `GIT_CONFIG_GLOBAL` and `GIT_CONFIG_SYSTEM` both `/dev/null`, `GIT_TERMINAL_PROMPT=0`, `GIT_AUTHOR_NAME`/`GIT_COMMITTER_NAME` `GopherMind`, `GIT_AUTHOR_EMAIL`/`GIT_COMMITTER_EMAIL` `gophermind@localhost`, and `GIT_OPTIONAL_LOCKS=0`. **Behavior rules:**
- **Listener.** `New` parses `Listen` with `net.SplitHostPort`; the host must parse as a loopback IP (`127.0.0.1` or `::1`) or `localhost`; else `proxy: listen address must be loopback`. Port 0 picks a free port (X5); `Addr()` is the real one. The proxy never listens on anything else and starts no other listener.
- **Requests.** Plain HTTP requests carry an absolute URL and are forwarded with a dedicated `http.Transport{Proxy: nil, DialContext with Dial timeout}`; `CONNECT host:port` is dialed with the same timeout, answered `200 Connection Established`, then bytes are copied both ways until either side closes (TLS stays opaque). Requests without an absolute URL (a direct hit on the proxy port) get 400.
- **Match.** Host is lowercased, a trailing dot and the port removed. Exact rule host, or `*.suffix` matches `a.suffix` and `a.b.suffix` but not `suffix` or `xsuffix`. An IP-literal host matches only an exact IP rule. **Loopback and unspecified destinations are denied unless an exact rule lists them** (defense against using the proxy to reach local services; real loopback traffic bypasses the proxy through `NO_PROXY`, Task 1a). No rule cares about the port.
- **Denied** requests get `403` with an empty body, and one log line with `verdict: "denied"`. A denied request to a host that matches a critical rule (the rule host with any `*.` prefix removed, compared exactly or as a suffix of the requested host, so `crit.test` requested against a `*.crit.test` critical rule counts) is recorded as a `Failure{Kind:"denied"}`.
- **Attribution.** The node comes from the `Proxy-Authorization: Basic` username `node-<id>` (Go's client sends it from the proxy URL's userinfo, for plain requests and CONNECT), else from `X-GopherMind-Node`, else `-`. `<id>` must match `^[A-Za-z0-9_.-]{1,64}$` else the node is `-`. `Proxy-Authorization`, `X-GopherMind-Node` and hop-by-hop headers are stripped before forwarding. The password is ignored (loopback only; the sandbox and the listen rule are the gate).
- **Log line** (JSON, one per completed request, exactly these fields and no others): `time`, `node`, `method`, `host`, `port`, `verdict` (`allowed|denied|error`), `status` (0 for CONNECT and errors), `bytes` (response body bytes or tunnel bytes both ways), `duration_ms`. There is no path, query, header value or body in the log struct, in any error, or in any `Failure`. A test greps.
- **Critical failure** (spec 14): a request to a host matching a rule with `Critical: true` that is denied, cannot be dialed (`unreachable`), times out (`timeout`), or (plain HTTP only) gets a 5xx from upstream (`5xx`) is recorded as a `Failure` for that node. A failure to a non-critical rule host is recorded as a warning only. `Failures` and `Warnings` are read by the executor after every command; nothing in `proxy` fails an attempt itself.
- **Streak.** `Observe(node, true)` three times in a row returns `terminal == true` on the third call and keeps returning true until a `false` resets; `Observe(node, false)` resets to zero; counters are per node; `Import` replaces state; `Export` returns a copy. Safe for concurrent use.
- The proxy never follows redirects (`CheckRedirect` returns `http.ErrUseLastResponse`), so an allowed host cannot bounce a request to a denied one under the proxy's name.

- `deriveImports`: parse `package p\n` plus the source with `go/parser`, walk for selector expressions whose qualifier is an identifier not declared in the file. An unresolved qualifier is an error `type <id>: cannot resolve package qualifier (<n> bytes)`. The resolved paths then go to `pol.Check`; any returned path is `type <id>: import not allowed (<n> bytes)`. Errors never quote source text.
- `WriteTypes` groups `Type`s by `File` in contract order, writes each file through `pathsafe.Replace` (`ResolveSource`), and returns the sorted paths. A file is `package <Type.Package>`, a sorted import block, then each `Decl` separated by a blank line, then formatted with `go/format`; a parse or format failure is `type <id>: declaration does not parse (<line>:<col>)`. It writes nothing when any type of the run fails (validate all first, then write all).
- `StubSource` produces `package <pkg>`, the import block it is given, the signature, and the body exactly `panic("gm: not implemented")` (S3: a `panic` terminates, so no returns follow and `go vet` stays quiet); the result passes `go/format`. Method signatures (`func (s *T) M() error`) are supported.
- `Swap` (spec 8.1, invariants): `Enter` = `pathsafe.Remove(stub)`, then `pathsafe.Replace(real)`; if `Replace` fails, `Enter` rewrites the stub before returning the error. `Fail` = `pathsafe.Remove(real)` then `pathsafe.Replace(stub, stubSrc)`; both steps run even when the first errors; idempotent.
```go
func ScanGoMod(src []byte) []Finding {
	var out []Finding
	inBlock := ""
	for i, raw := range strings.Split(strings.ReplaceAll(string(src), "\r\n", "\n"), "\n") {
		line := raw
		if j := strings.Index(line, "//"); j >= 0 {
			line = line[:j]
		}
		f := strings.Fields(line)
		if len(f) == 0 {
			continue
		}
		if inBlock != "" {
			if f[0] == ")" {
				inBlock = ""
				continue
			}
			if inBlock == "replace" {
				out = append(out, Finding{Kind: "replace", File: "go.mod", Line: i + 1})
			}
			continue
		}
		switch f[0] {
		case "replace", "toolchain":
			out = append(out, Finding{Kind: f[0], File: "go.mod", Line: i + 1})
			if len(f) >= 2 && f[1] == "(" {
				inBlock = f[0] // block form: every entry is a finding for replace; toolchain has no block form
			}
		case "require", "exclude", "retract", "godebug", "tool", "ignore":
			if len(f) >= 2 && f[1] == "(" {
				inBlock = f[0]
			}
		}
	}
	return out
}
```

**Behavior rules:**
- **Claim.** `runLeaf` expects a `ready` row: `Board.Claim` (false is an error: another worker owns it), `SetStatus claimed -> in_progress`, then a goroutine calls `Board.Heartbeat` every `executor.heartbeat_seconds` (or `rc.heartbeat` when set by a test) until `runLeaf` returns. - **The stub is always restored.** `runLeaf` creates the `Swap` once (`NewSwap(repo, l, git, stubFor(...))`; `in.Repair > 0` calls `Reopen`) and holds `defer func(){ if !passed { _ = swap.Fail() } }()`. No other code path leaves a real file on disk for a leaf that is not `verified`.
- **Files already on disk first (spec 7.2, 10 step 5).** Before any model call `runLeaf` calls `swap.Normalize()` (a fresh leaf has only its stub, so this is a no-op) and, when the real file exists (`SwapRealOnly`), runs `rc.checkLeaf` on it. If the file is already committed (not in `git.Dirty()`), `git.LeafCommit(id)` (Task 6) supplies its hash and the leaf is adopted without a second commit; otherwise a pass commits (`Swap.Pass`). Either way a pass ends `verified` with zero provider calls. A failure seeds the previous failure with `failureOf(verdict)` (runner output, in memory, no model cost) and the ladder starts at rung 2. A committed file that fails its check puts the swap in reopen mode so `Fail` restores it from git. This is the code Task 14's resume tests exercise; it is here because the leaf loop must handle a file a previous run left, resumed or not.
- **Entries and rungs (spec 7.3), per revision `r`:** for each `ladderEntry` `e` in order: attempt `k = 0` (initial), then up to `executor.fix_attempts` fix attempts, each with the previous failure. Every call is `router.CallParsed` with `CallInfo{RunID, Stage: "implement:"+id, NodeID: id, Tier: e.Tier, Scope: ScopeNode, Revision: r, TaskType: "implement", NodeClass: l.Class, Only: e.Name}` and `provider.Request{Messages: [system packer.SystemPrefix+"implement:"+id, user packed.Text], MaxTokens, Temperature: fixTemperature(k)}` (the router sets the model from `Only`). Moving from one entry to the next appends `report.Escalation{Kind: "model", TaskType: "implement", Model: next.Name}` to `_state/escalations.json`. With one entry the loop has no next entry, so no rung is empty and no call is wasted. A model entry is never tried twice in one revision.
